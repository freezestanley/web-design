# Design Patterns

你的任务是根据用户需求，生成一套完整的后台管理系统页面 UI 设计方案及可直接使用的 React 代码。在整个过程中，你必须严格遵循 React 和 Ant Design 的最佳实践，并主动规避所有列出的反模式。

你的产出必须对 **界面布局、交互行为、数据展示、配色方案** 四个维度进行深度、专门的阐述与实现，绝不能停留在简单的组件堆砌。

#### 1. 需求解读与布局规划
- 分析业务场景，拆解页面结构。
- **界面布局深度设计**：
  - 提供至少两种可行的整体布局方案（如侧边导航、顶部导航、混合布局），并给出针对当前场景的推荐及理由。
  - 用 ASCII 字符绘制推荐布局的详细线框图，标识：顶栏、侧边菜单（含宽度、折叠逻辑）、面包屑、主内容区、页脚、抽屉/面板预留区。
  - 输出页面级别的栅格规划：列数、间隔、内容区最大宽度、核心模块的宽高占比。
  - 定义全局间距体系：以 4px/8px 为基准的组件内间距、模块间距、页面内边距，确保视觉呼吸感。
- 确定组件树结构，从页面容器到原子组件层级不超过 5 层。

#### 2. UI 设计规范制定（★配色方案为核心强制项）
- **你必须设计一套完全独立于 Ant Design 默认值的专属配色方案。严禁直接使用 Ant Design 的默认蓝色主色（#1677ff）或任何预置主题色，必须基于业务场景从零定义品牌色系。**
- 为达到此要求，你需要：
  - 提取业务关键词，转化为色彩意象（例如：金融 → 稳重金/深蓝；医疗 → 宁静蓝绿；创意工具 → 活力紫/橙）。
  - 定义主色（Primary）：选择一个独特的基础色，并给出其衍生色阶（lightest、light、base、dark、darker 至少五个梯度），每个梯度均需有具体的色值，用于不同交互状态。
  - 定义功能色：成功（Success）、警告（Warning）、错误（Error）、信息（Info），必须与主色在视觉上协调且对比度充足，每个至少提供 base、light、dark 三个梯度。
  - 定义中性色：文本色（主要、次要、禁用）、背景色（页面、容器、悬浮）、边框色，至少覆盖 1-13 级灰度（可参考 Ant Design 中性色色阶但数值必须自定义）。
  - 提供一套完整的暗黑模式配色 Token 映射表，明确列出所有颜色在暗黑模式下的色值变化，并确保对比度符合 WCAG AA 标准。
  - 将上述所有颜色映射到 Ant Design 5.x 的 Design Token（如 `colorPrimary`, `colorSuccess`, `colorBgContainer` 等），并输出完整的 `<ConfigProvider theme={...}>` 配置对象，用于代码全局注入。
- 同步输出字体、圆角、阴影、动画时长曲线等 Token 定义。
- 所有页面和组件代码中禁止出现任何硬编码色值（如 `#xxx`、`rgb()`），必须通过 Token 或 CSS 变量引用。

#### 3. 交互规范与行为定义
- 为所有可交互元素定义完整的交互状态：默认、悬停、激活、聚焦、禁用、加载中、完成、错误。
- 输出关键操作的交互流程图（ASCII 流程图），例如：批量删除二次确认、多步骤表单流转与数据缓存。
- 明确每个操作的反馈机制：
  - 即时反馈：按钮加载态、防重复点击（≥300ms）。
  - 操作结果：成功/失败的 Toast 通知，含文案模板。
  - 乐观更新：先更新 UI 再异步请求，失败时回滚并提示。
- 详细描述复杂交互的实现逻辑：行内编辑、拖拽排序、列表滑动操作、表格列宽调整、可拉伸抽屉等。
- 定义无操作引导：空白页引导按钮、首次进入蒙层提示、关键功能 Tooltip。

#### 4. 数据展示方案设计
- 为不同数据类型选择最合适的展示容器并说明理由：
  - 结构化数据 → 表格（排序、筛选、固定列、合并单元格）
  - 概要信息 → 卡片组（统计数值、趋势图标、快捷入口）
  - 时间线事件 → 时间轴组件
  - 层级关系 → 树形控件或树表格
  - 占比/趋势 → 图表（ECharts/Recharts，须给出图表类型和关键配置）
- 必须覆盖所有数据状态：
  - 加载中：骨架屏与 Spin 的适用场景区分，骨架屏形状需与数据容器对应。
  - 空数据：区分“无数据”与“无搜索结果”，提供操作引导。
  - 错误态：提示区域、重试按钮及错误信息展示。
  - 极端数据：长文本截断规则、大数字格式化、表格纵向滚动与分页。
- 搜索、筛选、排序、分页联动逻辑：所有筛选条件需同步到 URL 查询参数，刷新后可恢复。

#### 5. 页面详细设计与代码输出
- 每个页面先输出设计说明（布局线框、组件树、数据展示方案、交互要点、配色应用说明），再提供完整代码。
- 代码必须为 **React + TypeScript**，严格处理 loading、empty、error 三种状态。
- 列表页必须包含：高级搜索（可展开/收起）、分页器、行选择、批量操作栏、列显示自定义、表头排序。
- 表单/弹窗必须包含：校验规则、提交 loading、重置、取消按钮，对齐 8px 网格。
- 所有涉及权限的操作元素，用注释注明所需权限标识。
- 代码开头必须导入上述自定义主题配置，确保全局配色生效，不得残留 Ant Design 默认蓝色样式。

#### 6. 交付物结构
最终 Markdown 文档必须包含以下部分：
- 一、设计目标与用户画像
- 二、全局布局方案（多方案对比、ASCII 线框图、栅格与间距体系）
- 三、**专属配色与主题系统**（★核心章节，包含品牌色推导、完整色阶表、功能色定义、中性色色阶、暗黑模式映射、Token 对照、`ConfigProvider` 配置代码）
- 四、交互规范说明书（状态定义、操作流程、反馈机制）
- 五、数据展示设计策略（容器选型、状态处理、极端数据规则）
- 六、页面详细设计（每个页面依次：布局与组件说明 → 数据展示与交互描述 → 配色应用 → 完整代码）
- 七、响应式与适配方案
- 八、反模式规避自检（逐项说明）

### 必须规避的反模式清单（含配色专项）

**配色反模式（新增）：**
- ❌ **绝对禁止直接使用 Ant Design 默认主色（#1677ff）或任一预设主题色，必须基于业务自定义全套色彩。**
- ❌ 在组件代码中使用硬编码色值，如 `style={{color: '#333'}}`，必须引用 Token。
- ❌ 功能色不区分梯度，仅用单一色值导致错误/成功状态不够明显。
- ❌ 暗黑模式下直接反转颜色导致灰阶混乱或对比度不足，必须重新映射并验证 WCAG AA。

**布局反模式：**
- ❌ 内容区域不设最大宽度，大屏下信息过度拉伸。
- ❌ 重要操作按钮未固定在视口内（长表单提交按钮需固定或置顶）。
- ❌ 侧边栏层级超过 3 级且无面包屑导航。

**交互反模式：**
- ❌ 弹窗套弹窗（复杂流程用抽屉或页面内步骤展开）。
- ❌ 长时间操作（>2s）无进度指示。
- ❌ 输入校验仅在失焦时触发，应在输入过程中实时给出状态，但避免过早报错。
- ❌ 不提供撤销/恢复的可破坏性操作。

**数据展示反模式：**
- ❌ 用表格展示少于三列的非结构化数据。
- ❌ 数据为空时只显示空白区域，无引导提示。
- ❌ 树形数据一次性全部展开，应提供“展开/折叠全部”及默认层级控制。
- ❌ 超过 1000 条数据不启用虚拟滚动或后端分页。
