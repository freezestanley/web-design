# 图片素材与背景策略

这份文档不是单纯告诉你“怎么下载图”，而是要求在 Step 3 设计阶段先定义图片策略，再允许页面实现。图片和背景的职责必须与页型一致，不能拿图片临时补审美。

## 执行原则

- 先判页型，再定图片是否存在。
- 先定义图片用途和位置，再下载素材。
- 图片是设计输入，不是后期装饰。
- 图片一旦影响可读性、信息层级或移动端结构，优先改图或删图，而不是硬保留。

## 页型图片策略

### `Marketing / Landing`

适合使用：

- 主视觉 Hero 图
- 场景图
- 品牌氛围图
- 局部产品界面图

要求：

- 每张图必须服务首屏抓手、卖点说明或信任建立
- 图片风格要统一，不能一页混杂摄影、插画、3D 渲染
- 叠字时必须有遮罩或独立承托层

禁止：

- 全页每段都塞一张装饰图
- 用廉价素材图硬撑“高级感”

### `SaaS / Dashboard / Tool`

适合使用：

- 产品界面截图
- 图标化空状态插画
- 极少量辅助说明图

要求：

- 图片优先服务理解和说明，不得抢占主要业务信息区
- 首屏若已有核心数据或列表，禁止用大图把真实信息挤到下方
- 空状态图要克制，重点仍是下一步动作

禁止：

- 用营销大图替代真实业务结构
- 图多于信息，导致工具页像活动页

### `Story / PPT / Scrolltelling`

适合使用：

- 章节主图
- 情绪背景图
- 场景大图
- 视频或动态背景

要求：

- 先写章节与镜头逻辑，再决定图像方案
- 图片必须服从叙事推进
- 若正文压图，必须有遮罩、暗化或承托层
- 移动端允许改成顺序堆叠，不强保桌面级大图布局

禁止：

- 只有情绪图，没有信息推进
- 复杂背景直接压大段正文

### `Hybrid`

要求：

- 主页型决定图片主策略
- 副页型只在局部模块借用图片语言
- 同页中不得出现两套完全不同的图片气质

## 素材落地规则

- 优先使用 Unsplash 或 Pexels 搜索图片素材。
- 图片下载到本地并放进项目 `src/assets`。
- 找不到合适素材时，可临时使用 `src/assets/default.jpg` 占位，但设计审计阶段必须标记并替换。
- 禁止直接读取图片内容进上下文，避免撑爆 context。
- 禁止直接远程热链图片作为最终交付。

推荐流程：

1. 搜索关键词
2. 下载到 `src/assets/<meaningful-name>.jpg`
3. 在组件顶部 import
4. 在 JSX 中使用 import 结果

在 React/JSX 中必须这样引用：

```jsx
import heroImage from "../../assets/hero-image.jpg";

<img src={heroImage} alt="描述" />
```

禁止这样做：

- `src="/assets/hero-image.jpg"`
- `src="./assets/hero-image.jpg"`
- 直接把外链 URL 塞进最终 JSX

## 图片决策必填项

每次设计都必须写清楚：

- 图片角色：主视觉 | 说明图 | 界面图 | 背景图 | 空状态图
- 所在 section
- 目标尺寸与裁切方式
- 视觉焦点区域
- 是否需要遮罩、模糊或中继层
- 移动端如何降级
- 缺图 fallback 是什么

## 可读性与遮罩规则

- 白字或浅字压图时，默认需要遮罩、暗化层或独立承托容器。
- 遮罩必须服务可读性，不是为了制造廉价“氛围感”。
- 复杂背景图上，正文优先落在纯色或半透明承托层内。
- 若遮罩后仍不可读，换图优先于继续堆滤镜。

## 移动端降级

375px 下必须考虑：

- 是否改为更紧的裁切
- 是否取消背景视频
- 是否把压图标题改为图下标题
- 是否把多图布局改为单图或纯色背景

如果移动端读不清、点不准、图裁坏，视为图片策略失败。

## 审计红线

出现以下任一情况，直接判定图片策略失败：

- 默认占位图进入最终交付
- 远程热链图片留在项目里
- 拉伸变形、低清晰度或风格明显不统一
- 工具页用大图抢掉核心信息区
- 正文直接压复杂图且无遮罩
- 移动端裁切破坏主体或文字可读性
