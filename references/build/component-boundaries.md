# Component Boundaries

开发阶段默认按职责拆分，避免单文件巨石实现。

## Default Split

- **UI 组件**：负责结构、样式、展示
- **hooks**：负责状态、交互逻辑、生命周期
- **services**：负责接口请求与数据访问
- **页面容器**：负责编排各区块，不承载所有细节

## Practical Rules

- 不把逻辑和 UI 长篇混写在同一个页面文件里
- 不把接口请求直接散落在多个展示组件中
- 不把所有 section 都写成一个上千行组件
- 不为了省事破坏复用边界

## When to Split

出现以下任一情况就该拆：

- 某个组件开始承载多段不同职责
- 某块逻辑会被多个组件消费
- 接口访问逻辑变复杂
- 页面结构已经分成明显区块

## When Not to Over-Split

也不要为了形式主义把极小的静态片段拆成十几个文件。

原则：

- 以可维护性为主
- 以任务边界为主
- 以复用与理解成本为主
