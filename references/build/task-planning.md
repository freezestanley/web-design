# Build Task Planning

开发阶段的计划必须落在磁盘文件中，而不是堆在上下文里。

## Rules

- 先写任务计划，再写实现
- 一次只执行一个明确子任务
- 当前子任务未完成前，不跳到下一个
- 不把整份计划全文塞进 context

## Recommended Task Shape

每个子任务应当尽量小而明确，例如：

- 实现 Hero 容器与布局
- 实现卖点卡片组件
- 接入空状态插图与文案
- 补齐某个 hook 或 service

避免这种大任务：

- “把整页全部写完”
- “把所有组件和逻辑都补上”

## Plan Storage

建议把计划存进当前 task 的工作文档，例如：

- `task.md`
- 其他当前任务目录下的计划文件

读取策略：

- 需要时再读
- 用完就回到当前子任务

## Execution Discipline

- 单任务执行
- 单组件或单模块推进
- 每次改动都能明确说明“这次只完成了什么”
