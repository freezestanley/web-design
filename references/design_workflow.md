# Web 设计工作流

这份文档是 `web-design` 在 Step 3 开发前必须读取的设计执行规程。它只负责三件事：

1. 先把页面分型
2. 再把设计输入补齐
3. 最后把差页面拦在开发前和审计门外

它不是工具宣传页，也不是通用灵感收集页。真正的 `DESIGN.md` 模板以 `references/design_v2/design.md` 为准，真正的实现与审计提示分别以 `references/design_v2/design-taste-frontend.md` 和 `references/design_v2/gpt-taste.md` 为准。
若需要看填写方式，可额外参考 `references/design_v2/example-marketing-design.md` 与 `references/design_v2/example-saas-design.md`。

## 执行总则

- 进入 Step 3 后，先判定页型，禁止先选工具再倒推页面长相。
- 未完成 `DESIGN.md` 前，禁止进入代码开发。
- 未定义图片策略前，禁止引入任何大图、背景图、视频或占位图。
- `references/design/template.md` 可作为历史示例阅读，但不再是权威模板。
- Step 3 产出的设计输入必须服务于当前页面类型，而不是套用通用“高级感”空话。

## Step 3 硬顺序

### 1. 页型分流

先把当前页面归入以下 4 类之一：

| 页型 | 主目标 | 默认风险 |
|------|--------|----------|
| `Marketing / Landing` | 转化、品牌记忆点、卖点表达 | 容易做成普通模板页或视觉噪音堆叠 |
| `SaaS / Dashboard / Tool` | 可扫读、规整、业务效率 | 容易退化成廉价后台风 |
| `Story / PPT / Scrolltelling` | 章节推进、镜头感、情绪沉浸 | 容易炫技过度或信息难读 |
| `Hybrid` | 同时承载叙事与业务模块 | 容易主次混乱、两边都不像 |

`Hybrid` 必须额外声明：

- 主页型
- 副页型
- 副页型只允许影响哪些局部模块

### 2. 读取本地设计资料

按页型读取本地资料，禁止全读一遍后自己脑补。

| 页型 | 必读资料 | 关注重点 |
|------|----------|----------|
| `Marketing / Landing` | `references/design/landing.md` | Hero 锚点、卖点分段、CTA 节奏、社会证明 |
| `SaaS / Dashboard / Tool` | `references/design/landing.md` 中可转化部分 + 当前项目现有 UI | 信息层级、筛选区、数据区、空状态、组件秩序 |
| `Story / PPT / Scrolltelling` | `references/design/ppt.md`, `references/design/story.md` | 章节推进、镜头感、分幕节奏 |
| `Hybrid` | 先读主页型对应资料，再补读副页型资料 | 主骨架由主页型决定，副页型只做局部增强 |

有背景、视频、粒子、光影、长图等需求时，再补读：

- `references/design/background.md`

图片素材与背景图的使用规则，统一读取：

- `references/image.md`

### 3. 先定图片策略，再定版式

图片不是装饰补丁，而是设计输入的一部分。每次都必须先回答：

- 这页是否真的需要图片
- 图片承担的是主视觉、说明、情绪、产品演示还是只做背景
- 图片会放在哪个 section
- 是否需要遮罩、裁切、焦点保护
- 移动端如何降级
- 若图片缺失，页面是否仍然成立

没有这 6 个答案，视为设计输入不完整。

### 4. 工具选择顺序

先定页型，再定工具。推荐顺序如下：

| 角色 | 工具 | 使用原则 |
|------|------|----------|
| 基础实现引擎 | `design-taste-frontend` | 默认必经，负责整页结构和实现气质 |
| 审美纠偏层 | `gpt-taste` | 在设计定稿前和审计阶段都要使用 |
| 滚动叙事引擎 | `gsap-scrolltrigger` | 只有 `Story / PPT / Scrolltelling` 或明确滚动叙事时才允许接入 |
| 微交互补强 | `motion.js`, `React Bits` | 只补局部完成度，不能接管整页结构 |
| 业务控件层 | `antd` | 仅 `SaaS / Dashboard / Tool` 或 `Hybrid` 的业务模块中按需使用 |

禁止行为：

- 普通工具页强行做成 scrolltelling
- 营销页默认接入 `antd`
- 先决定“上 GSAP / React Bits”，再倒推设计
- 把 `React Bits` 当整页模板来源

## 页型分流细则

### `Marketing / Landing`

必须产出：

- 强 Hero 锚点
- 明确的卖点分段
- 至少一个可信任背书区
- 清晰 CTA 主次关系
- 背景或图片策略

禁止做成：

- 纯卡片平铺的后台首页
- 所有 section 同节奏、同容器、同留白
- 全页只有渐变背景，没有主视觉抓手

### `SaaS / Dashboard / Tool`

必须产出：

- 明确的信息层级
- 搜索、筛选、状态标签、数据概览的组织方式
- 空状态、加载态、异常态的视觉预案
- 低装饰但不廉价的表面质感

禁止做成：

- 纯白背景加默认蓝按钮
- 大图抢占首屏，压缩真正的业务信息
- 所有数据模块都长得一样，缺少主次层级

### `Story / PPT / Scrolltelling`

必须产出：

- 章节顺序
- 每章的叙事目标
- 是否需要 sticky、reveal、timeline 或滚动场景切换
- 移动端降级方案

禁止做成：

- 长列表直接堆到底
- 为了炫技引入重滚动效果，但没有叙事收益
- 文字直接压复杂图且无遮罩

### `Hybrid`

必须产出：

- 主页型
- 副页型
- 两者交界点
- 哪些模块允许保留叙事感，哪些模块必须回到工具秩序

禁止做成：

- 首屏像营销页，后半段突然切成默认后台
- 业务模块和叙事模块共用同一套节奏，导致两边都失真

## `DESIGN.md` 必填项

`DESIGN.md` 必须以 `references/design_v2/design.md` 为模板，并至少包含：

- 页面身份：页型、主目标、受众、场景、验收结果
- 设计指纹：`DESIGN_VARIANCE`、`MOTION_INTENSITY`、`VISUAL_DENSITY`
- 视觉关键词：最多 5 个，必须可落到结构或质感
- Section Blueprint：每个模块的顺序、职责、核心内容和移动端折叠方式
- 图片与背景策略：来源、位置、用途、遮罩、降级、占位方案
- 组件语言：按钮、卡片、标签、筛选、图文、数据块如何统一
- 动效策略：允许的动效和禁止的动效
- 响应式降级：375px 下如何保住信息结构
- 负向红线：明确什么情况直接判设计失败
- 自检表：进入开发前逐项确认

以下情况直接视为 `DESIGN.md` 不合格：

- 只有颜色和字体，没有 section 级结构
- 视觉关键词都是空泛形容词，如“高级、简约、现代、科技”
- 没写图片用途和遮罩策略
- 没写移动端降级
- 没有按页型说明失败红线

## Step 3 内部 Gate

### G3.1 页型确认门

必须确认当前页面属于哪一类；未确认前禁止选工具。

### G3.2 素材策略门

必须先定义图片和背景策略；未定义前禁止下载或引用素材。

### G3.3 设计规约门

必须完成 `DESIGN.md`；未完成前禁止进入组件拆分和页面开发。

### G3.4 设计确认门

必须由用户确认 `design.md`；未确认前禁止推进开发。

### G3.5 审计回退门

若审计触发 FAIL，必须回退到 `DESIGN.md` 或开发阶段修正，禁止只修表面样式继续往前走。

## 审计输出要求

Step 3 的审计不只检查页面能不能打开，还要检查页面是否符合页型目标。`audit.md` 除了现有运行检查外，新增以下维度：

- 页型匹配结论
- 视觉层级结论
- 信息密度结论
- 图片与背景可读性结论
- 移动端降级结论
- 模板味风险结论
- 必改项列表

建议结构如下：

```md
## Design Audit
pageType: Marketing | SaaS | Story | Hybrid
overall: PASS | FAIL

### Fit
- 页面是否真的符合该页型目标

### Visual Hierarchy
- 主次是否拉开

### Density
- 信息是否过稀或过挤

### Image Safety
- 图片是否影响可读性

### Mobile
- 375px 是否仍成立

### Template Smell
- 是否出现通用模板味

### Required Fixes
- 必改项 1
- 必改项 2
```

## 失败红线

出现以下任一情况，直接判 FAIL：

- `DESIGN.md` 缺页型、section 骨架或移动端降级
- 营销页做成后台列表风
- 工具页做成大图堆叠风，业务信息难扫读
- 故事页没有章节推进，只是普通长页面
- 白字直接压复杂图且无遮罩
- 空状态仍使用默认占位图或一句裸文案塌在中间
- 页面整体结构、卡片、CTA、节奏明显呈现模板味

## 执行提示

进入设计或重设计时，按这个最小顺序推进：

1. 判页型
2. 读对应资料
3. 读 `references/image.md`
4. 写 `DESIGN.md`
5. 用 `gpt-taste` 做一次设计自审
6. 用户确认 `DESIGN.md`
7. 再进入开发
